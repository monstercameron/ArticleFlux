Speculative decoding without a draft model

Opened 84% 6 min read 1,420 words Median dwell 4:10 Reader mode

Every speculative decoding writeup starts the same way: you need a small draft model to propose tokens and a large model to verify them. That framing is doing a lot of work, and most of it is unnecessary.

The draft model exists to produce a cheap guess. But a guess is just a distribution you already have lying around — in the prompt, in the n-gram statistics of the document you are generating, or in the model's own earlier layers. Each of those is free.

The cheapest version is embarrassing in its simplicity. Keep a rolling n-gram table of the text generated so far. When the next token has been seen following this prefix before, propose it. Verify it in the same batched forward pass you were going to run anyway.

On a 27B model quantized to four bits, running on an NPU with a narrow memory bus, this cut wall-clock generation by 31% on structured output and did essentially nothing on free-form prose. That gap is the whole story, and it is worth sitting with before reaching for a second model.
