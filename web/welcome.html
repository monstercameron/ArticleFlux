Self-hosted feed reader

Your reading is nobody else's business.

Google Reader died in 2013 and what replaced it was a choice: somebody else's server holding your reading history, or a PHP app from 2011 with a mobile site that does not work.

ArticleFlux is the third option. One binary, one SQLite file, no runtime dependencies — and a client that is a real application rather than a page. Virtualised lists at firehose scale, full-text search, tags, notes, offline reading, and a voice that will read an article to you.

The unusual part is what is not here. No JavaScript framework, no bundler, no npm install, no REST layer translating between two halves of one program. The server is Go. The client is Go compiled to WebAssembly. The stylesheet is Go. The only JavaScript that ships is a boot shim that loads the module.

Claim this server Try the demo first

Claiming takes a username and a password. No account exists yet — the first person to set one owns this instance.

It fetches on your behalf, carefully

Every outbound request goes through an SSRF guard: link-local addresses and the cloud metadata endpoint are unreachable on any configuration, and an IPv4 address wearing an IPv6 costume is still that address.

Nothing leaves the box unless you turn it on

Fonts are served from here, not from a CDN that would learn your IP on every load. The optional Smart+ features — a voice, translation, a summary written for the ear — are off until you add a key, and off again the moment you remove it.

Popular feeds are polled once

Sources and items are global and deduplicated; subscriptions are yours. A feed a hundred people read is fetched once for all of them, and what you have read is nobody's business but your own.
